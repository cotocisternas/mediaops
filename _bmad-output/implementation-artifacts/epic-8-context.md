# Epic 8 Context: Move the library, render the docs

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

The home disk is the library of record, and identity is TitleId, not a path string. This epic lets an operator move that archive to a new disk or machine without hand-editing schema roots, systemd units, or title-index paths, and replaces tribal SEEDBOX.md / AGENTS.md with docs generated from PathSchema so scan rules cannot lie.

## Stories

- Story 8.1: Library relocate and new-machine
- Story 8.2: docs render from PathSchema

## Requirements & Constraints

- `library relocate` rewrites schema roots, systemd-user units, and title-index paths when the library moves — through the config and store owners, never by hand.
- `new-machine` export bundles desired-state + the gitignored tls dir + the title index (install digests included). Import populates the active config dir and machine state — never a git work tree. Layout bootstraps even before media files exist.
- Loss of `state.db` without an export means reclaim has no proof: refuse until `library reindex` re-hashes local files. No digest, no remote delete. Size/mtime is not proof.
- Re-mint is the TLS disaster path. Cert PEMs are gitignored next to desired-state; desired-state stores fingerprints and paths, never PEMs. Doctor refuses PEMs inside a git work tree; bootstrap refuses to mint certs into one.
- `docs render` generates operator docs from PathSchema, not hand-edited path lists. EncodePolicy packs remain the encoder inputs so docs and code cannot drift on scan rules. A test must cite the "docs vs code" named failure.
- Identity is TitleId (kind + TMDB / TVDB / MBID). The title index maps TitleId → path → inode / BLAKE3 so identity survives rename. Music remasters key by MBID, not folder year.
- Schema dirs stay `movies` / `series` / `music` plus app-managed `_ops` / `_incoming` (never media-server libraries). This is not a Jellyfin/Plex installer; if a server already scans `_incoming` or `_ops`, warn and do not reconfigure.
- Scheduler remains systemd-user oneshot + `OnUnitInactiveSec` + flock — all three. No overlapping `OnCalendar` cron.
- Every verb takes `--json`. Stdout is a human result or a single `{ok, data, error}` envelope; stderr is tracing (JSON lines when not a tty). The CLI talks only to local mediaopsd over a unix socket and never contains a seedbox address.
- Default tests never need network, the live box, or a GPU. Named failures that need tests: docs vs code (SEEDBOX.md lying about scan paths; encode policy not matching docs); cert PEMs committed or sitting inside a git work tree.

## Technical Decisions

**Where it lives.** Relocate, new-machine, and docs render are home-side. `core::pathschema` is the only renderer/parser of library paths; every other crate treats those paths as opaque. Title-index export/import is a `store` API; repository traits live in `core`; binaries inject the adapter; neither daemon role links `store`. Home mediaopsd is a gateway and never writes staging or library paths.

**Config layout.** Active config defaults to `~/.config/mediaops/` (`desired-state.toml` + `tls/`). Machine state lives in `~/.local/state/mediaops/` (XDG). Desired-state may be versioned in the repo of record; the active dir itself is never a work tree. Three tiers: user-edited desired-state, app-owned machine state (sqlite + probes), runtime artifacts (lockfile, `.partial`, tls PEMs, plans). Nothing app-owned is user-edited; nothing user-edited is machine-written except by an explicit command that shows a diff.

**Title index and proof.** One home `state.db`, touched only by `store` (rusqlite behind `spawn_blocking`). `title_index` carries `install_b3` (immutable reclaim proof) and `current_b3` (updated only by the install gate). Relocate rewrites stored paths; it does not add a third library-path writer. Install and replace remain the only install-gate entry points.

**Units and exec.** systemd-user `mediaops-run.service` (oneshot) + `mediaops-run.timer` (`OnUnitInactiveSec`) are generated by library bootstrap; relocate rewrites them. `systemctl` goes through the shared exec port with probed absolute paths in machine state — no lib bindings.

**Locks.** `docs render` is lock-free (single-transaction store writes only). Bootstrap is exclusive. Relocate, new-machine, and reindex are not named in the lock table; they still mutate config and store through the same owners as bootstrap. The flock-holding CLI is the executor.

**Exits.** `core` owns ExitCode: 0 ok, 1 runtime, 2 usage, 3 lock conflict, 4 drift/verify, 5 policy refusal. Libraries never `exit`.

**v1 topology.** One seedbox + one home disk. Multi-box / multi-disk is deferred; relocate moves that one library and does not add a topology registry.

## UX & Interaction Patterns

CLI-first; no separate UX contract. TUI is deferred and will attach to the tracing stream. Operator surface: `library relocate`, `new-machine` export/import, `docs render`, plus `library reindex` as the digest rebuild fallback. Timers never require a TUI.

## Cross-Story Dependencies

- 8.1 and 8.2 are independent: mobility vs generated docs. No required order.
- Depends on Epic 3: `library bootstrap` already stands up schema dirs, watermarks, lock, systemd-user oneshot + timer, and `title_index`. This epic rewrites and exports that layout; it does not re-invent bootstrap.
- Depends on Epic 1: TitleId, PathSchema as the only renderer/parser, DesiredState, store repository traits.
- Epic 7 already refuses reclaim when `install_b3` is missing. This epic owns `new-machine` export (digests included) and `library reindex`.
- CAP-11, TUI, `ui <app>`, bearer-token 2FA, and a generalized wants queue stay deferred. PathSchema remains the only writer for later agent proposals.
