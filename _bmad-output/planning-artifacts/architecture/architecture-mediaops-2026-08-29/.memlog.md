- (decision) Single wire-schema source: mediaops-proto owns all .proto files (package mediaops.v1), tonic-build/prost codegen at build time; proto depends on core and is the sole home of wire-to-domain From/TryFrom conversions. Wire evolution additive-only within v1; removal or retyping means a new proto package version.
- (decision) [ASSUMPTION] Executor split: the CLI process holding the machine-global flock is the executor of plan/apply/encode/verify/install; home mediaopsd is an overlay gateway only — holds the mTLS client identity, re-serves the seedbox services on the UDS, proxies control and Range streams, never writes staging or library paths, owns no job logic. Keeps lock semantics honest (work never outlives the flock holder) and gives staging a single writer.
- (decision) One mediaopsd binary, role from its config: seedbox role binds TCP gRPC+mTLS serving Control + Transfer + localhost grabber HTTP clients; home role binds the unix socket as gateway. Reverse-connect stays a designed-unused mode of the same binary.
- (decision) Persistence: one home sqlite state.db accessed only by the store crate (rusqlite behind spawn_blocking); embedded migrations via PRAGMA user_version; tables title_index, jobs, probes, holds_decisions. Other crates consume typed repository traits. Seedbox daemon keeps no sqlite in v1 (allowlist walk + arr are its truth).
- (decision) Three data tiers, each value in exactly one: (1) desired-state TOML — user-edited, git-versionable, snapshot per plan; (2) machine state — sqlite + probe results (Range N, NVENC cap, binary paths), app-owned, never git; (3) runtime artifacts — lockfile, .partial + range map, tls/ dir. Budgets/policies are tier 1; probe outcomes tier 2.
- (decision) [ASSUMPTION] Config home: default ~/.config/mediaops/ holding desired-state.toml + tls/ (+ .gitignore minted at bootstrap). Bootstrap refuses to mint certs into a git work tree; doctor refuses PEMs found inside one. Resolves the spec tension between desired-state lives in the home repo and no PEMs in a work tree: the ACTIVE config dir is outside any work tree; the user versions desired-state.toml in the repo of record however they like (copy or symlink source-to-active is their call).
- (decision) [ASSUMPTION] .partial format: staging file <final-name>.partial plus sidecar <final-name>.partial.b3 (JSON, version field, {file_len, range_len, ranges:[{offset, len, blake3}]}). A range is completed only after its bytes are fsynced and its hash recorded in the sidecar. Whole-file BLAKE3 computed on the staged file, then atomic rename into the schema path; install digest recorded in title_index. Resume = read sidecar, trust recorded ranges, continue.
- (decision) Range concurrency: probed N = number of independent TCP+TLS gRPC channels, one in-flight GetRange stream per channel. Naive tonic channel reuse would multiplex all streams onto one HTTP/2 connection — exactly the collapse-onto-one-TCP failure the spec names. Slot scheduler fills channels files-first, then splits the largest remaining file into ranges. Fixed default range_len 64 MiB [ASSUMPTION], a desired-state value, not autotuned in v1.
- (decision) [ASSUMPTION] Exit codes: core owns exhaustive ExitCode enum — 0 ok, 1 runtime failure, 2 usage (clap), 3 lock conflict, 4 drift/verify failure (doctor drift, hash mismatch), 5 policy refusal (watermark breach, encode Refuse, upgrade refuse). Library crates return thiserror enums and never call exit; binaries map error to ExitCode in one place.
- (decision) [ASSUMPTION] Output convention: stdout carries only the command result — human text, or with --json a single envelope {ok, data, error:{code, message}}; stderr carries tracing events (JSON lines when stderr is not a tty). Progress is tracing events; the deferred TUI attaches to that stream, never a second progress channel.
- (decision) PathSchema single writer at crate level: only core::pathschema renders/parses library paths; the install gate API consumes (TitleId, verified staging handle) and returns the installed path; all other crates treat library paths as opaque. One walker in core enforces the remote-root allowlist and never follows symlinks off it — every listing (daemon Transfer service, planner input) goes through it.
- (decision) arr transport port: the arr crate speaks HTTP through an HttpTransport trait; production impl is reqwest (only inside mediaopsd); tests replay recorded cassettes (JSON request/response fixtures) through the same trait. Cassettes are the failure-history vehicle for every named grabber failure.
- (decision) Subprocess port: ffmpeg/ffprobe/ssh/systemctl are invoked through a single exec port with probed absolute paths persisted in machine state. No lib bindings anywhere: no ffmpeg-next, no ssh2/russh. System ssh binary honors ~/.ssh/config Host seedbox natively, which is why shelling out beats a Rust SSH lib here.
- (decision) TLS identity: net crate mints via rcgen an ECDSA P-256 [ASSUMPTION] CA + server + client cert at seedbox bootstrap into tls/{ca.pem, server.pem, server.key, client.pem, client.key}; desired-state stores SHA-256-of-DER lowercase-hex fingerprints [ASSUMPTION: the BLAKE3-only lock is scoped to content digests; cert fingerprints stay SHA-256 for openssl interop]. rustls everywhere, native-tls forbidden. Server requires-and-verifies client certs against the CA; client trusts only the minted CA.
- (decision) Plan artifact: JSON, embeds the full desired-state snapshot plus its hash; apply reads config only from the plan, never re-reads disk (no hot-reload mid-copy by construction). Action is an exhaustive Rust enum {Copy, Skip, Review, Unmonitor, DeleteRemote, Encode, Reclaim, EdgeApply, GrabApply} — workspace exhaustive-switch rule applies. run = plan then apply of that exact artifact in the same locked process.
- (decision) Jobs: every long-running operation is a jobs row with a typed per-kind state machine (want, pull, encode, hold); timer-invoked run advances ready jobs under ResourceBudget and exits; crash recovery derives from job state + runtime artifacts (.partial sidecar), never from guesswork. State transitions are the only writes to jobs.
- (decision) Dependency rules are CI-enforced: a workspace test walks cargo metadata and asserts arr appears only in the mediaopsd tree; reqwest confined to arr; the cli tree excludes arr and reqwest; transfer excludes reqwest and ssh; rsync/rclone/ftp/ssh2/russh crates appear nowhere. This is the executable form of the no-rsync-ssh-symbol failure-history test.
